# 城市公共自行车站点满桩调拨与维修平台

## 原始需求

开发城市公共自行车站点满桩调拨与维修平台，可使用 Vue 3、Go 和 PostgreSQL。用户借车时，平台核验账户、押金、车辆编号、站点状态和骑行限制；还车时，平台记录桩位、车辆锁止、费用、故障反馈和用户位置。运营端实时查看站点满桩、空桩、车辆故障、调拨车位置、早晚高峰需求和地铁口客流。若用户到站无法还车、站点无车、车辆刹车异常、锁具打不开、调拨车堵在路上或某站点长期潮汐失衡，平台要把用户、客服、调度员、维修员和站点管理员放到同一事件里处理。调拨策略需要考虑地铁早高峰、学校放学、商圈活动、维修车辆比例和调拨车容量。维修入库后，车辆故障类型、维修用时、配件消耗、重复故障和是否报废进入档案；站点调整时，运营可以看到用户流失、满桩投诉和调拨成本。平台还要把调拨车司机班次、站点电源、车辆清洗、用户骑行禁区、恶劣天气停运和地铁突发客流纳入运营判断。站点策略变化会影响用户通勤，所以调度动作需要能解释给客服和城市管理方。用户申诉时，平台要能从一次骑行回到借车桩位、还车状态、客服处理和调拨影响，运营需要判断费用、车辆和站点责任分别来自哪里。

## 本轮新增原始需求

增加高峰调拨路线。早高峰前，平台根据地铁口取车需求、住宅区还车积压和调拨车容量生成路线。调度员执行时，站点库存、车辆状态和预计到达会实时更新，偏离路线会影响后续站点补车。路线偏离如果是道路拥堵造成，调度员可以补充原因，避免司机被错误考核。偏离原因会进入调拨复盘，用于优化下一次路线。路线复盘会关联高峰天气。

### 新增需求 → 实现对照

| 需求点 | 实现 |
|---|---|
| 早高峰前按地铁口取车需求 + 住宅区还车积压 + 调拨车容量生成路线 | `POST /api/peak-routes/plan`：读 7 点（晚高峰 18 点）分时段需求预测，计算住宅装车点与地铁口卸车点，贪心装载并受车容量约束，生成有序多站路线与中文解释 |
| 调度员执行：站点库存 / 车辆状态 / 预计到达实时更新 | 详情页执行中 5 秒轮询；到达登记移动调拨车坐标并重算后续 ETA；装卸在事务内真实移动车辆（在桩⇄在途、占用/释放桩位），车上数量与站点库存实时变化 |
| 偏离路线影响后续站点补车 | 晚点到达自动判偏离，并给出对后续卸车站点的顺延影响；前车装车不足会级联导致后站少补，复盘统计「少补车辆」 |
| 道路拥堵可补充原因、免司机错误考核 | `POST .../stops/{seq}/deviation`：校验客观原因关键词（拥堵/管制/事故/恶劣天气等）才允许豁免；非客观原因勾豁免被拦截 |
| 偏离原因进入复盘、优化下一次路线 | `POST .../review` 汇总偏离/豁免/准点率/少补并归类原因；历史复盘的「道路拥堵」次数会让下一条路线自动预留行车缓冲 |
| 路线复盘关联高峰天气 | `peak_weather` 表按日期+早/晚高峰录入，复盘自动关联；橙/红预警路线再追加缓冲；复盘列表与偏离台账均展示天气 |

## 本轮新增原始需求（二）：重复故障报废评估

增加重复故障报废评估。同一车辆多次出现刹车、车锁或轮胎问题时，平台汇总维修记录、骑行里程和配件成本。维修主管可决定继续维修、限制投放或报废，结果影响车辆资产台账。报废决定会同步到采购计划和站点可用车预测，防止账面有车但现场无车。报废车辆若仍在站点显示，系统会触发资产状态复核。资产复核会通知维修仓。

### 新增需求 → 实现对照

| 需求点 | 实现 |
|---|---|
| 同一车辆多次出现刹车 / 车锁 / 轮胎问题 | `GET /api/assets/candidates`：按三类关键故障次数≥2 或存在重复维修筛选候选车 |
| 汇总维修记录、骑行里程、配件成本 | 评估单汇总：各类故障次数、30 天重复次数、维修次数、累计里程（还车时按行程累加 `mileage_km`）、配件成本（配件单价×用量）、工时成本，并给出系统建议（继续维修 / 限制投放 / 报废） |
| 维修主管裁决：继续维修 / 限制投放 / 报废 | 新角色「维修主管」`lead1`；`POST /api/assets/assessments/{id}/decide` 三种裁决，普通维修员只能查看/回收、无权裁决 |
| 结果影响车辆资产台账 | 裁决写入 `vehicle_assets`（在役 / 限制投放 / 已报废、累计维修成本、里程、账面净值） |
| 报废同步采购计划 | 报废自动在 `procurement_plan` 生成 1 辆补货需求（含来源评估单与原因） |
| 同步站点可用车预测，防账面有车现场无车 | `GET /api/assets/forecast`：可用车只计「在桩且未限投」，剔除故障/在修/在途/限投/报废，叠加未来 3 小时借还需求算缺口；单列「账实异常」 |
| 报废车仍在站点 → 触发资产状态复核 | 裁决/报废时扫描仍占用桩位的报废/限投车辆，自动建 `asset_reviews` |
| 资产复核通知维修仓 | 复核单 `notified_warehouse=true`，维修仓可「受理 / 现场回收销账」，销账释放桩位、车辆清出站点、账面与现场恢复一致 |

## 本轮新增原始需求（三）：满桩还车引导

增加满桩还车引导。用户到站发现无空桩时，平台根据附近站点空位、步行距离、超时状态和用户信用推荐还车点。若用户接受引导，费用计算暂停；若附近无空位，客服可生成临时还车处理单。临时还车单需要绑定车辆照片和用户位置，客服审核后才关闭计费。临时处理单关闭后，用户端会看到费用调整理由。照片要包含站点编号。

### 新增需求 → 实现对照

| 需求点 | 实现 |
|---|---|
| 满桩时按附近空位 / 步行距离 / 超时 / 信用推荐还车点 | `POST /api/rides/return-guidance`：**必须携带用户实际触发满桩的目标站点 `station_id`**，以该站（如 ST04）坐标折算步行距离/分钟就近列出空桩站（不回退借车站；目标站仍有空位会提示直接还车）；超 2 小时标超时，高信用（≥90）优先提示最近站 |
| 接受引导 → 费用暂停 | `POST /api/rides/guidance/accept`：`rides.fee_paused/fee_pause_time`，费用封顶在接受时刻；在推荐站点正常还车时按暂停时刻计费，步行与找桩时间不收费 |
| 附近无空位 → **客服生成**临时还车处理单 | `POST /api/temp-returns` 限**客服/运营**（普通用户与非客服员工返回 403）：用户在满桩页点「联系客服」自动建协同事件；客服在「临时还车审核」页选进行中行程生成，行程转 `temp_pending`、车辆转 `temp_locked`（不可借、不占可用车），审核期间保持停止计费 |
| 绑定车辆照片（含站点编号）+ 用户位置 | 客服端调用相机拍照，画布叠加「站点编号 + 时间」水印后上传（data URL）；后端强制照片、位置，并校验填写编号与满桩站点编号一致、且该站确实无空桩 |
| 客服审核后才关闭计费 | `POST /api/temp-returns/{id}/review`：通过必填费用调整理由、可设免除额，关闭计费并通知调度回收；驳回则行程恢复进行中、继续计费 |
| 关闭后用户端看到费用调整理由 | 用户行程列表显示状态、最终费用、减免金额与 `fee_adjust_reason`；引导还车同样写入调整理由 |
| 客服工作台 | 「临时还车审核」（`/temp-returns`）：「＋客服生成临时还车单」（选进行中行程+满桩站+照片+位置）、照片放大核对站点编号、超时/暂停费用、通过（可设免除额）/驳回（必填理由） |

## 技术栈

- **前端**：Vue 3 + Vite + Vue Router + ECharts（构建产物由 Go 内嵌伺服）
- **后端**：Go 1.23（标准库 `net/http` 路由 + `lib/pq`），REST API，Token 会话
- **数据库**：PostgreSQL 16（首次启动自动建表 + 灌入演示数据）

## 一键启动（Docker）

```bash
cp .env.example .env        # 可选，默认值即可运行
docker compose up -d        # 构建并启动 app + db
docker compose ps           # 查看健康状态
```

- 应用端口通过环境变量 `CC_PUBLISH_PORT` 发布到宿主（compose 写法 `${CC_PUBLISH_PORT}:8080`）。
- 实际映射端口可用 `docker compose port app 8080` 查询，然后访问 `http://localhost:<端口>`。
- 数据库不发布宿主端口，仅在 compose 内部网络以服务名 `db` 访问。
- 停止：`docker compose down`（加 `-v` 可同时清空演示数据）。

   - 对 `BK0040`「生成评估单」→ 查看汇总的维修履历/里程/配件+工时成本 →「裁决」选**报废**：车辆退役、**自动生成采购计划**、从可用车预测剔除；因车仍在桩，系统**自动触发资产复核并通知维修仓**；
   - 切「资产复核（维修仓）」→ 换 `repair1` 登录，对各条「受理 → 现场回收销账」，桩位释放、账面与现场一致；
   - 「站点可用车预测」核对：可用车只计在桩可投放车，报废/限投/故障均剔除，缺车站点给出缺口，防止账面有车现场无车；
   - 「资产台账」看在役/限投/报废与账面净值，「采购计划」看报废同步的补货行。（普通维修员/调度员只能查看，无裁决按钮。）
9. **【满桩还车引导 / 临时还车单】**：
   - `cs1` 打开「临时还车审核」：`rider4` 一笔满桩临时还车单待审，放大照片可见站点编号 **ST04**、已超时、暂停时费用 ¥6；填费用调整理由、设免除 ¥4.5 → **通过并关闭计费**；换 `rider4` 在「借车/还车」看到最终 ¥1.5、减 ¥4.5 与**费用调整理由**；
   - 用 `rider1` 借车后向「万象城商圈站」（**ST04 满桩**）还车被拦截 → 点「满桩智能推荐还车点」：推荐**以 ST04 为中心**按步行距离列出周边空桩（最近为中心医院站），显示已骑行时长/**超时**与**信用分** → 「接受引导·费用暂停」→ 在推荐站点还车，**费用封顶、找桩时间不计费**；
   - 周边无空位时，用户点「联系客服生成临时还车单」自动建协同事件；**普通用户无法自建临时单（接口 403）**；客服在「临时还车审核 → ＋客服生成临时还车单」选进行中行程、选满桩站、上传**含站点编号的车辆照片**并填用户位置（编号不一致/站点有空位/缺照片或位置均被拒）→ 审核前**计费保持暂停** → 通过须填调整理由，用户端可见；驳回则行程恢复进行中继续计费。

## 验证方式

本项目以「宿主 `docker compose up` 健康 + 关键业务流走通」为验证标准：

```bash
docker compose up -d --build
docker compose ps                                  # app/db 均 healthy
PORT=$(docker compose port app 8080 | cut -d: -f2)
curl -s "http://host.docker.internal:$PORT/api/health"            # {"status":"ok"}
# 登录 → 借车 → 还车 → 事件 → 调拨/高峰路线 → 维修/报废评估 → 申诉，均可通过界面或 API 走通
docker compose down
```

### 重复故障报废评估 API 一览

| 方法与路径 | 角色 | 说明 |
|---|---|---|

| `POST /api/assets/assessments` | 维修主管 | 汇总生成报废评估单 |

| `POST /api/assets/assessments/{id}/decide` | 维修主管 | 裁决 continue/restrict/scrap，联动资产台账、采购计划、可用车预测 |
| `GET /api/assets/ledger` | 任意员工 | 车辆资产台账（在役/限投/报废、成本、里程、账面净值） |
| `GET /api/assets/procurement` | 任意员工 | 报废自动同步的采购补货计划 |
| `GET /api/assets/forecast` | 任意员工 | 站点可用车预测（剔除不可用车、算 3h 缺口、标账实异常） |
| `GET /api/assets/reviews` | 任意员工 | 资产状态复核（报废车仍在站时自动触发并通知维修仓） |

### 高峰路线 API 一览

| 方法与路径 | 角色 | 说明 |
|---|---|---|
| `POST /api/peak-routes/plan` | 调度员/运营 | 依据地铁取车需求、住宅还车积压、车容量生成有序多站路线（含复盘学习缓冲） |
| `POST /api/peak-routes/{id}/assign`、`/start` | 调度员/运营 | 派车（校验容量）、出车开始执行 |
| `POST /api/peak-routes/{id}/stops/{seq}/arrive` | 调度员/运营 | 登记到达：移动车辆坐标、实时重算后续 ETA，晚点自动判偏离并提示影响 |
| `POST /api/peak-routes/{id}/stops/{seq}/execute` | 调度员/运营 | 装车/卸车：真实移动车辆与桩位，更新车上数量与站点库存，末站自动完成 |
| `POST /api/peak-routes/{id}/stops/{seq}/deviation` | 调度员/运营 | 补充偏离原因；道路拥堵等客观原因可豁免司机考核 |
| `POST /api/peak-routes/{id}/review` | 调度员/运营 | 复盘：准点率/偏离/豁免/少补、关联当日高峰天气、产出优化建议 |
| `GET /api/peak-routes`、`/{id}`、`/deviations`、`/reviews` | 任意员工 | 路线、执行详情、偏离台账、复盘列表 |
| `GET/POST /api/peak-weather` | 员工 / 调度员·运营 | 高峰天气查询与录入（复盘自动关联） |
